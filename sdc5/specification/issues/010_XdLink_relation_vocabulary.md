# SDC5 Issue: A Recommended Relation Vocabulary for `XdLink` (Correlation, Trace, Derivation)

**Filed**: November 11, 2026
**Priority**: Low
**Affects**: `XdLinkType` (`relation`, `relation-uri`) guidance; published component library
**Discovered during**: Governed event (logging) mapping, Issue 008
**Raised by**: T. Cook (RM owner), 2026-11-11

## Problem

Correlating records across sources (the same trace, the same session, the event
that caused this one, the record this one replaces) is done in SDC4 with `XdLink`:
`link` (target), `relation` (required string) and `relation-uri` (optional).

That mechanism is sufficient, but `relation` is free text and no recommended
vocabulary exists. Each modeller invents a term: `correlates-with`,
`correlationId`, `related`, `sameTrace`. Two models can then express the same
relationship in ways a processor cannot match, which defeats the cross-source
correlation the link exists for.

## SDC4 position (works today)

Any model can bind `relation-uri` to a published term. The gap is only the
absence of a recommended set, so consistency depends on each modeller.

## SDC5 recommendation

1. **Publish a short recommended relation set**, each term with a `relation-uri`
   reusing existing vocabularies where they exist (W3C PROV-O, Dublin Core terms,
   IANA link relations), rather than minting SDC terms. Candidates:
   - correlation: same trace, same session or transaction, correlates with;
   - causation and sequence: caused by, follows, part of;
   - versioning: replaces, is replaced by, is version of;
   - derivation: was derived from, was generated by (aligned with Issue 003).
2. **Guide text**: always set `relation-uri` when a recommended term exists; use
   free-text `relation` alone only for model-specific relationships.
3. **Reusable components** in the library for the most common correlation links
   (for example, a trace-correlation `XdLink`) so models reuse the binding.

No RM change is proposed. A conformance rule ("`relation-uri` required when a
recommended term applies") could be considered but is not recommended: it cannot
be checked mechanically.

## Domain neutrality check

Neutral. The relations are generic and drawn from existing open vocabularies.

## Compatibility

Guidance and components only; SDC4 and SDC5 unchanged.
